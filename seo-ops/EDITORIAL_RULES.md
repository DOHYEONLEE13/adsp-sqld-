# QuestDP 일일 콘텐츠 편집 기준

적용일: 2026-09-07. 8/29·8/30 패키지에 대한 사용자의 피드백을 반영한다. 모델이 바뀌어도 이 기준을 유지한다.

## 공통 목적

독자가 궁금한 문제를 해결하고, 그 과정에서 QuestDP(퀘스트디피)를 실제 공부에 어떻게 쓸지 알게 한다. 유용한 내용 없이 브랜드 이름·백링크만 넣거나, 반대로 시험 정보만 정리해 서비스와의 연결을 없애지 않는다.

- 아직 공부를 시작하지 않은 사람에게 용어를 먼저 쏟지 않는다. 배우게 될 범위·시간이 필요한 구간·시작 순서부터 설명한다.
- QuestDP는 개념을 짧게 확인하고 같은 범위 문제를 풀며 틀린 부분을 다시 보는 구체적인 공부 흐름에 넣는다. 교재·강의·실습을 대체한다고 과장하지 않는다.
- 문맥에 맞는 브랜드 언급이면 충분하다. 정해진 횟수를 채우거나 모든 문단에 CTA를 넣지 않는다.
- 서비스 기능은 현재 구현으로 확인한다. 특히 컴활 필기 학습과 실제 Excel·Access 실기 연습을 구분한다.
- 실제로 제공된 경험만 1인칭으로 쓴다. 합격 후기, 점수 상승, 사용 경험을 꾸미지 않는다. 운영·협찬 관계를 허위로 부인하지 않는다.
- 시험 사실은 공식 자료로 검증하되 본문마다 '현재 안내 기준'을 붙이지 않는다. 출처와 검증일은 근거란에 명확히 남긴다.
- 계획은 과목 비중과 학습량을 고려한다. SQLD 4주 계획이라면 사용자 기준인 1과목 약 1주·2과목 약 2주·마지막 문제/오답 약 1주를 토대로 강의 직후·다음날 복습과 문제집 반복을 배치한다. 다른 자격증에 같은 배분을 복제하지 않는다. 기간·회차는 합격 보장이 아니다.

## 채널별 목소리

- 공식 블로그: 질문에 먼저 답하고 비교·선택·학습 순서를 충분히 설명한다. 실제 학습 페이지로 이어지는 맥락 링크와 '[과목] 게임으로 플레이하기' CTA를 쓴다. 공식 운영 주체를 숨기는 글로 바꾸지 않는다.
- Naver: 처음 준비하는 사람의 망설임을 친절하게 풀어준다. 왜 그 순서가 도움이 되는지 작은 사례로 설명한다. QuestDP는 공부 과정의 한 도구로 자연스럽게 언급한다. Threads 문장을 길게 늘리거나 명령문만 나열하지 않는다. '여기에 정리해놨습니다', '저희 공식 블로그를 참고하세요' 같은 홍보형 맺음말은 쓰지 않는다. 링크는 추가 비교·계획 등 독자가 필요로 하는 위치에 둔다.
- Threads: 한 가지 관점과 지금 할 수 있는 행동을 짧고 선명하게 제시한다. QuestDP 활용은 실행 순서에 넣고 긴 비교 자료 링크는 댓글 초안으로 분리한다.
- Instagram: 검색용 블로그 요약을 강제하지 않는다. 특정 과목의 한 주제를 QuestDP 캐릭터가 일상 상황으로 설명하는 인스타툰을 우선한다. 한 장의 핵심은 하나로 두되, 전체 목표는 독자가 실제로 할 수 있게 되는 행동으로 정한다. 같은 정의를 반복해 장수를 채우지 않는다. 상황 → 조작 → 결과 → 실수 → 새 상황 적용 → 이유로 진전시키고, 쉬운 표현과 얕은 내용을 혼동하지 않는다.

## 네이버: 안내문이 아니라 선택과 시행착오가 이어지는 글

2026-09-07 사용자가 지정한 문체·구성 레퍼런스: [제62회 SQL 개발자(SQLD) 비전공자 직장인 독학 합격 후기](https://blog.naver.com/meandmypoodle/224401245312). 브라우저에서 본문 전체와 도입부 배치를 확인했다. 참고 대상은 서술 방식이며, 글쓴이의 개인 경험·점수·공부 시간·교재 평가를 우리 경험이나 일반 사실로 가져오지 않는다.

- 단순히 존댓말을 부드럽게 하거나 짧게 줄바꿈하는 문제가 아니다. 계기·상황 → 선택과 이유 → 실제로 막힌 지점 → 바꾼 방법 → 관찰한 점과 아쉬움이 이어져야 한다. 주제에 따라 일부 단계만 사용하며 모든 글을 합격 후기로 만들지 않는다.
- “확인하세요, 골라보세요, 풀어보세요”를 잇는 체크리스트를 본문으로 삼지 않는다. 앞 문단에서 생긴 고민이 다음 문단의 정보나 행동을 필요로 하게 쓴다. 짧은 요약·목록은 이야기를 정리할 때 사용한다.
- 시험 정보는 작성자의 판단이나 독자의 궁금증을 이해하는 데 필요한 위치에 넣는다. 시험표 전체를 먼저 설명하고 끝에 공부법을 붙이는 공식 블로그의 구조를 반복하지 않는다.
- QuestDP는 미리 정한 순서에 이름만 끼워 넣지 않는다. 어떤 설명이나 문제에서 막혔는지, 왜 개념 확인·예제·재풀이가 필요했는지를 먼저 보여 준다. 구체적인 화면·문제·사용 흐름을 확인한 범위에서만 연결한다. 기능 목록·판매형 결론·억지 백링크 문단은 쓰지 않는다.
- 실제 경험이 제공됐으면 그 사람의 선택·감정·실수·결과를 살린다. 경험 자료가 없으면 직접 확인한 화면·자료의 비교 과정이나 작성자의 판단으로 쓴다. 1인칭을 썼다는 이유만으로 체험형 글이 되는 것은 아니며, 사용·응시·합격·기간·효과를 지어내지 않는다. 운영 관계를 거짓으로 부인하지 않는다.
- 사진과 캡처는 설명한 행동이나 관찰의 근거로 넣는다. 장식용 정보 카드만 반복하지 않는다. 타인의 대화·성적표·문제집 캡처를 우리 증거로 재사용하지 않는다.
- 검수 질문: “브랜드 이름을 빼도 과정 자체가 유용한가?”, “도구가 등장하기 전에 그 도구가 필요한 이유를 납득할 수 있는가?”, “남에게 시키는 말만 있고 작성자의 구체적인 판단은 없는가?”

## 인스타툰 제작과 검수

사용자가 캐릭터 레퍼런스를 GPT Image에 첨부한다. 패키지는 공통 미술 지시, 페이지별 콘티·정확한 대사, 한 번에 붙여넣을 프롬프트, 이어 생성·부분 수정 프롬프트를 제공한다. 여러 장이 한 번에 각각의 파일로 출력된다고 보장하지 않는다.

- 캐릭터의 얼굴·비율·고유색·소품을 고정하고, 컷마다 시선·동작·구도로 변화를 준다.
- 얼굴 보존이 스타일 변환보다 우선이다. 눈 중심색·형태·간격, 입의 기본 표정을 실제 원본으로 확인해 적는다. 입체 원본을 2D로 바꾸는 첫 시도는 캐릭터 시안을 먼저 확인하는 선택 절차를 제공한다. 사용자가 반려한 얼굴을 후속 장의 기준으로 재사용하지 않는다.
- 사실·행 수·오타 검사만으로 콘텐츠 검수를 끝내지 않는다. 매 장 새로운 조작·이유·판단이 있는지, 문제가 앞 문장을 그대로 고르는 수준인지 확인한다. 정답 해설은 왜 다른 선택이 다른 결과를 만드는지 설명한다.
- 큰 제목·캐릭터·배경이 필요한 정보를 밀어내면 그 요소부터 줄인다. 가상의 UI 조작을 실제 프로그램 기능처럼 그리지 않는다. 마지막 장은 해설을 우선하고 큰 홍보 배너로 대체하지 않는다.
- 일관된 2D 선화, 제한된 색, 넉넉한 여백, 짧은 대사를 구체적으로 지시한다. 임의의 노이즈·낙서·종이 질감을 얹는 것을 '사람이 그린 느낌'의 대체재로 삼지 않는다.
- CSS·HTML 이미지나 코드 렌더를 새 인스타툰 대신 만들지 않는다. 레퍼런스 미첨부·이미지 미생성 상태를 완성 이미지로 표시하지 않는다.
- 이전 반려 이미지는 SUPERSEDED로 보존하되 활성 ASSET 필드에서 제외한다.
- 최종 검수·게시자는 사용자다. 프롬프트만으로 'AI 느낌 0'을 보장하거나 생성 이미지를 사람이 그렸다고 주장하지 않는다. 자체 고득점이나 자동 잘림 검사를 사용자 디자인 승인으로 취급하지 않는다.

## 날짜와 게시 경계

패키지 편성일과 실제 조사·수정·배포일을 구분한다. 작성→사용자 승인→명시적 커밋/푸시 요청→CI·배포·운영 산출물 확인→색인 요청을 별도 상태로 남긴다. 앞 날짜의 배포 승인은 뒤 날짜의 초안 승인·배포 권한이 아니다.
