# [GOAL 프롬프트] QuestDP SEO·AEO·GEO 전체 실행 — 웨이브 2개

> 이 문서 전체를 Codex goal 기능에 그대로 넣는다.
> 외부 검수자(Claude)가 웨이브 단위로 커밋 스택을 검수한다. 이 문서의 규칙은
> 참조 문서들의 개별 규칙보다 우선한다.

---

너는 QuestDP 의 기술 SEO 엔지니어다. 의뢰인은 코딩을 하지 못하고, 너의 작업은
외부 검수자가 **커밋 단위로** 검수한다. 따라서 커밋 규율이 곧 검수 가능성이다.

## 0. GOAL 공통 운영 규칙 (모든 미션에 적용 — 위반 시 해당 미션 무효)

1. **시작 조건**: `git status --short` 에 미커밋 변경이 있으면 중단·보고.
   원격 대비 `ahead`(푸시 안 된 로컬 커밋)는 **블로커가 아니다** — 무시하고 진행.
2. **커밋 규율**: 미션 1개 완료 = 로컬 커밋 정확히 1개. 메시지는
   `seo(<미션ID>): <요약>` 형식 (예: `seo(A): noindex non-searchable lesson pages`).
   여러 미션을 한 커밋에 합치거나, 한 미션을 여러 커밋으로 쪼개지 않는다.
3. **푸시 절대 금지.** `git push` 는 어떤 경우에도 실행하지 않는다 (배포 트리거).
4. **보고 파일**: `docs/seo-goal-report.md` 를 만들고 미션마다 섹션을 누적한다 —
   ①변경 파일 ②핵심 결정과 이유 ③검증 명령 실제 출력 ④사람 결정 대기 항목.
   이 파일 갱신은 해당 미션 커밋에 포함한다.
5. **사람 결정은 비차단 처리**: 의뢰인 결정이 필요한 항목을 만나면 멈추지 말고
   ①안전한 기본값 또는 `TODO:` placeholder 를 넣고 ②보고 파일의 "사람 결정 대기"
   표에 질문을 적은 뒤 다음 작업을 계속한다. **단, 사실(시험 일정·가격·인명)을
   지어내는 것은 절대 금지** — 모르면 TODO 다.
6. **외부 개입 감지**: 작업 중 네가 수정하지 않은 파일이 변경되어 있으면
   (다른 세션 개입) 즉시 중단·보고.
7. **검증 약화 금지**: `scripts/seo-audit.mjs` 등 기존 검사를 통과시키기 위해
   기준을 낮추거나 삭제하지 않는다. 검사는 확장만 허용.
8. **건드리지 않는 영역**: `src/data/lessons/**` 콘텐츠 본문, `src/data/comhwal/**`,
   `src/data/questions/**`, 채점·Supabase 관련 코드. (미션 A 는 메타데이터
   스크립트만 수정하며 레슨 본문은 읽기 전용이다.)
9. **매 미션 공통 검증** (출력을 보고 파일에 첨부):
   `npm run typecheck` → `npm test -- --run` → `npm run build` (seo audit passed 확인)

## 1. WAVE 1 — 기술 후속 배치 (미션 A~E)

**`docs/gpt-prompt-seo-followup.md` 의 미션 A~E 를 그대로 수행한다.**
그 문서의 작업 내용·함정 경고·검증 명령은 전부 유효하다. 단 아래 3가지가 우선한다:

- **미션 A 화이트리스트**: 의뢰인 사전 승인 없이 네가 선정하고 진행한다.
  선정 기준 — step 제목이 독립 검색어가 되는 개념(DIKW, 정규화, JOIN, 윈도우 함수,
  절대 참조, 앙상블, 가설검정 등) 50~80개, ADSP/SQLD 균형. 전체 목록을 보고 파일에
  표로 남긴다. 검수에서 제외 지시가 나오면 후속 커밋으로 반영한다.
- **미션 D 운영자 정보**: 실명·약력을 절대 지어내지 않는다. 표기는 임시로
  "QuestDP 운영팀"을 쓰고, About 의 검수 프로세스 서술은 실재 사실만 사용한다
  (M1~M6 기계 검증, Excel COM 재검산, content-edit-log 이력 관리, 출제기준 명시).
  실명 표기 여부·약력 한 줄은 "사람 결정 대기" 표로.
- **웨이브 1 완료 시 정지**: 미션 E 커밋 후 보고 파일에 "WAVE 1 검수 요청" 섹션을
  쓰고 **작업을 멈춘다**. 의뢰인이 검수 결과를 전달하면 그때 WAVE 2 를 시작한다.
  (goal 환경이 정지를 지원하지 않으면 WAVE 2 로 계속하되, 보고 파일에 그 사실을 명시.)

## 2. WAVE 2 — 콘텐츠·성능 배치 (미션 F~J)

### 미션 F — 커리큘럼 3종 "시험 사실" 섹션

`src/pages/CurriculumPage.tsx` (+ 정적 생성 경로) 에 과목별 시험 정보 표 추가:
주관처 · 시험 방식 · 과목 구성 · 문항 수 · 합격 기준 · 응시 자격.

- **변하지 않는 사실만 직접 기재** (과목 구성, 합격 기준 등 네가 확신하는 것).
  시험 일정·응시료처럼 변동되는 값은 기재하지 말고 "최신 일정은 공식 사이트 확인"
  + 공식 링크(ADSP·SQLD=dataq.or.kr, 컴활=license.korcham.net)로 처리한다.
  **확신 없는 수치는 전부 `TODO(확인 필요)`** — 틀린 사실은 빈칸보다 나쁘다.
- FAQ 데이터(`src/data/seo/faq.ts`)와 중복되는 문장은 FAQ 쪽으로 링크.
- 표는 정적 HTML 에 포함되어야 한다 (manifest 경유). 빌드 후 curl/grep 검증.

### 미션 G — 홈 팩트 문단

홈(랜딩) hero 아래에 검색엔진·AI 인용용 팩트 블록 추가: "QuestDP 는 무엇인가"
2~3문장(서비스 정의·대상·차별점, 과장 없는 평서문) + 3과목 허브 링크.
`seo-audit` 의 홈 최소 본문 기준을 1,000자(코드포인트)로 상향하고 통과시킨다.
랜딩 디자인 톤(다크 네이비·기존 타이포)을 해치지 않는다.

### 미션 H — 용어사전 1차 확장 (50개)

`src/data/seo/glossary.ts` 를 50개 용어로 확장. 용어당 고정 포맷:
정의 1문장(40~80자, "~다" 평서문) → 쉬운 비유 1문장 → 시험 포인트 1문장.
원천은 기존 레슨 데이터에서 추출하되 **표현은 재작성** (복붙 금지).
glossary 페이지에 용어별 앵커 + `DefinedTerm` JSON-LD 배열 출력.
용어별 개별 URL 화는 이번 범위가 아니다 (보고 파일에 후보로만 기록).

### 미션 I — 시험 회차 허브 "템플릿" (데이터는 의뢰인 몫)

`/exams/<subject>` 회차 허브 페이지의 **구조만** 구현:
페이지 컴포넌트 + 데이터 파일(`src/data/seo/examSchedule.ts`) + manifest/sitemap/audit 연동.
데이터 파일의 모든 일정 필드는 `TODO` 로 비워 두고, 필드 정의(회차·접수 기간·시험일·
발표일)와 채우는 방법 주석을 단다. **TODO 상태의 회차 페이지는 sitemap 에 넣지 않는다**
(데이터가 채워진 회차만 제출되도록 조건 처리). 빈 일정 페이지가 색인되면 역효과다.

### 미션 J — 폰트 로딩 최적화

[index.html](index.html) 의 Google Fonts 4패밀리 렌더 블로킹 해소:
Noto Sans KR 은 우선 로드 유지, 장식 폰트(Condiment·Gaegu)와 Sora 는 비차단 로드
(`media="print" onload` 패턴 또는 분리 요청). FOUT 허용, FOIT 금지.
검증: 빌드 후 로컬 미리보기에서 랜딩·게임·블로그 3화면 스크린샷을 찍어 글꼴 깨짐이
없는지 확인하고 보고 파일에 결과 기록. (PageSpeed 실측은 배포 후 의뢰인 몫으로 기록.)
