## 1. 미션 (한 문단)

QuestDP 의 컴퓨터활용능력(컴활) 필기 학습 콘텐츠 152개 토픽 중, 이미 기준 품질로 재작성된 8개를 제외한 **144개 토픽의 개념 카드와 확인 문제를 실제 시험 대비가 가능한 수준으로 전면 재작성**한다. 코드 로직은 건드리지 않는다 — 콘텐츠 데이터만 바꾼다.

## 2. 왜 하는가 (사전 감사 결과)

2026-06-10 감사에서 확인된 사실:
- 컴활 카드 374장 중 사람이 만든 문제는 12개뿐. 나머지는 `방금 본 "${card.title}" 설명과 가장 가까운 것은?` 이라는 자동 생성 문장 복기 문제다.
- 자동 생성 오답은 **전 과목 공용 풀**에서 수식으로 뽑혀, 엑셀 문제에 Windows/Access 문장이 보기로 섞인다.
- 엑셀·액세스 토픽은 토픽당 저작 카드 2장(본문 70자)이 전부라 실제 출제 깊이(함수 세부 동작, 옵션, 함정)를 전혀 못 다룬다.
- 톤이 유아 동화 수준까지 내려간 카드가 많다 ("부탁을 바꿔 줄 친구가 필요해").

## 4. 절대 제약 — 위반 시 그 배치 작업은 무효

### 4-1. 서버 채점 구조 (가장 중요)

- 컴활 정답은 서버 RPC `private.comhwal_expected_answer_index` 가 **문제 ID 에서 공식으로 계산**한다: `((토픽번호 - 행성기준) + (문제번호 - 1)) % 4`. 클라이언트 `buildQuestion` 이 같은 공식으로 정답을 그 위치에 배치하므로, **너는 정답 위치를 신경 쓸 필요가 없고 신경 써서도 안 된다.** `correct` 와 `wrongChoices` 만 작성하면 배치는 자동이다.
- 서버 화이트리스트 `public.comhwal_lesson_questions` 는 **토픽당 q02, q04 두 문제만 허용**한다 (토픽 001만 q03/05/07/09).
- 따라서 **토픽당 저작 카드는 정확히 2장을 유지**한다. `getReinforcedTopicCards` 가 각 카드를 [도입 버블 + 본 카드(문제)] 쌍으로 펼쳐 q02/q04 가 된다. 카드를 3장 이상 넣으면 q06 이후가 서버에서 `unknown_question` 으로 거부되어 XP 가 조용히 사라진다. **카드 확장은 9절의 사전 승인 절차 없이는 금지.**

### 4-2. 테스트가 강제하는 형식 (concepts.test.ts)

- `title` ≤ 28자, `body`·`setupBody` ≤ 70자 (코드포인트 기준), `keyPoints` 3~5개.
- 금지 문자열(부분 일치): `입니다`, `합니다`, `이다`, `다음과 같이`. **`이다` 는 부분 일치라서 "쓰이다·보이다·높이다·줄이다" 같은 단어도 걸린다.** 어미는 반말(~야/~해/~돼/~줘)로 통일.
- 선택지 4개 모두 비어 있지 않고 서로 달라야 한다 (`correct` ≠ 각 `wrongChoices`, wrongs 끼리도 중복 금지).
- 문제 프롬프트에 `에서 방금 배운 핵심`, `문제를 풀어보자` 포함 금지.
- **토픽 001, 002 는 테스트가 내용을 고정(pin)하고 있다. 절대 수정 금지.**

### 4-3. 데이터 외 금지 사항

- `buildQuestion`, `pickQuestionChoices`, `getReinforcedTopicCards`, 테스트의 서버 공식 검증 로직 수정 금지.
- `expansionSubjects.ts` 의 토픽 id·제목 변경 금지 (로드맵 UI 와 1:1).
- 시나공·이기적 등 시판 수험서, 기출 복원 사이트의 문장 복붙 금지. 사실은 같아도 표현은 전부 오리지널로.
- Supabase 에 임의 마이그레이션 적용 금지. **콘텐츠만 바꾸면 서버 동기화가 필요 없다** (공식 채점 + ID 화이트리스트 불변이므로).

## 5. 골드 스탠다드 — 이 품질이 합격선이다

이미 재작성 완료된 8개 토픽을 먼저 정독하라. 너의 모든 산출물은 이 수준과 비교된다:

| 토픽 | 파일 | 보고 배울 것 |
|---|---|---|
| 030 주기억장치 | concepts.ts | DRAM/SRAM 4축 비교, 같은 도메인 오답 |
| 047 인터넷의 주소 체계 | concepts.ts | 숫자 스펙(32/128비트) 명시, DNS/DHCP 함정 |
| 070 사용자 지정 서식 | expansionConcepts.ts | **계산형 문제** (3.5 + 0.00 → 3.50) |
| 073 셀 참조 | expansionConcepts.ts | **수식 복사 계산 문제** (=A1+$C$1 → =C2+$C$1) |
| 076 통계 함수 | expansionConcepts.ts | **데이터 제시형 문제** (COUNT 결과 숫자 고르기) |
| 082 찾기/참조 함수 | expansionConcepts.ts | "옳지 않은 것" 유형, 인수 구조 |
| 110 키(KEY) | expansionConcepts.ts | 한 글자 비튼 함정 보기 (NULL 허용) |
| 111 정규화 | expansionConcepts.ts | 목적 오해 함정 (속도 향상 X) |

카드 한 장의 필수 구성:

```ts
{
  title: '...',            // 개념의 핵심 주장 한 줄 (≤28자)
  setupBody: '...',        // 도입 버블 — 왜 필요한지/비유 (≤70자)
  body: '...',             // 시험에 나오는 사실 본문 — 구체 스펙·숫자·기호 포함 (≤70자)
  keyPoints: [...],        // 3~5개 — "구분 기준" 형태로. 'A: x / B: y' 패턴 권장
  examTip: '...',          // 실제 출제 함정 1개를 짚는다. 막연한 "자주 나와" 금지
  questionPrompt: '...',   // 필수. 실제 기출 스타일 발문
  correct: '...',          // 정답 텍스트
  wrongChoices: [...],     // 정확히 3개. 반드시 같은 도메인. 아래 6절 기준
  explanation: '...',      // 왜 정답인지 + 어떤 오답에 왜 속는지
}
```

## 6. 문제 작성 표준

1. **발문 유형 분배 (토픽 2문제 기준):** 최소 1문제는 ①계산/결과 예측형(엑셀 함수·서식·참조), ②사례 판별형, ③"옳지 않은 것" 형 중 하나. 단순 정의 재진술 2연속 금지.
2. **오답 3개는 같은 도메인의 실존 개념**이어야 한다. 좋은 오답 = ①형제 개념(DNS↔DHCP, COUNT↔COUNTA) ②한 단어만 비튼 참 문장 ③흔한 오해. 나쁜 오답 = 다른 과목 문장, 말이 안 되는 문장.
3. **두 문제가 같은 정답·같은 오답 세트를 재사용하면 안 된다.**
4. 함수 문제는 시험 표기 기준(엑셀 2021/M365 한글판, RANK.EQ·MODE.SNGL 등 현행 함수명)을 따른다.
5. 사실 검증: 확신이 없는 스펙(비트 수, 단축키, 기본값)은 작성 전에 교차 확인하고, 불확실하면 그 토픽을 보류 목록에 넣고 보고한다. **그럴듯한 추측으로 채우지 마라.**

## 7. 작업 순서와 배치

시험 비중과 사용자 노출 순서 기준:

- **Batch A — 스프레드시트 일반 060~106** (070/073/076/082 제외, 43개 토픽) ← 1·2급 공통, 최우선
- **Batch B — 컴퓨터 일반 003~059** (001·002 고정, 030/047 제외, 55개 토픽)
- **Batch C — 데이터베이스 일반 107~152** (110/111 제외, 44개 토픽)

각 배치를 **10~12 토픽 단위**로 쪼개고, 단위마다 8절 검증을 통과한 뒤 다음 단위로 간다. 한 번에 전부 고치고 마지막에 테스트하는 방식 금지.

## 9. 선택 과제 — 카드 2장 → 4장 확장 (별도 승인 필요)

토픽당 2문제로는 깊이가 부족한 토픽(예: 077 수학/삼각, 078 텍스트 함수)이 있다. 확장하려면:

1. 먼저 의뢰인에게 대상 토픽 목록과 함께 승인을 요청한다.
2. 승인 시 `supabase/migrations/0073_expand_comhwal_question_whitelist.sql` 을 작성해 해당 토픽의 `q06`, `q08` 을 `public.comhwal_lesson_questions` 에 insert (0072 의 `on conflict` 패턴 동일).
3. **마이그레이션이 라이브 DB 에 적용된 것을 확인한 후에만** 해당 토픽 카드를 4장으로 늘린다. 순서가 바뀌면 사용자 XP 가 조용히 증발한다.
4. concepts.test.ts 의 카드 수 가정이 깨지는지 먼저 확인한다.
